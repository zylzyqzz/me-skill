# 周五：同步个人仓库 main

安装时建立第二个独立任务，默认周五 09:00，采用 me.json 中已确认的时区。此任务只检查与升级，不收集聊天或制作周报。是否允许自动升级以当前用户明确选择与平台授权为准。

## 更新步骤

1. 读取实际安装路径、Git 来源、分支/提交、me.json、.local/onboarding.json。核验 origin 是配置中的个人私有仓库，已有权限仍有效。保留安装身份、证据、收据和两项任务。
2. 有本地改动、未跟踪文件、写入锁或活跃维护任务时保留现状，不 reset --hard/clean、不覆盖。用已有登录 fetch 个人仓库 main，固定候选提交 SHA。
3. 相同内容或只有 proposals 增加时不升级；远端比本机已验证维护版旧则不降级。同版本实际修复也可验证更新，汇报实际提交号。未合并 PR 不是正式版本。
4. 将候选导出到隔离临时目录，运行测试与 `python scripts/validate_package.py`（个人版本不加 --template），检查现有本地状态兼容性。准备旧提交/分支、个人全局区块及受影响本地状态的备份。失败不切换安装。
5. 正常 Git 安装只快进到核验过的 main SHA；维护分支须确认已合并，才能安全转回 main 并快进。历史分叉、未审核差异或权限问题保留原状并报告。ZIP 安装先在临时目录验证、迁移本机 .local 后再切换，不直接覆盖解压。
6. 更新后通过新版本 onboard.py 对原登记的同一用户级全局入口预览并 --write，保持其他规则。核验身份、周报收据、版本、全局区块及两个任务；必要的调度协议变化更新已有任务，不改变用户时区/通知偏好，不重复创建。
7. 成功才写 .local/update-state.json，记录检查时间、版本、SHA 与验证结果。切换后验证失败时安全回退本次变更；期间有新增修改不得覆盖，无法恢复则明确状态。没有更新安静结束，成功/失败/需用户处理时通知。

全局范围是当前宿主的用户级个人设置，覆盖不同项目和新对话。已有会话刷新依宿主，不能说更新文件会立即改变所有运行中的对话。

## 模板框架升级

公开模板与个人仓库分开：周五默认只同步个人仓库 main。不要从公共模板整体覆盖，否则会把配置和画像恢复为空。

需要新版框架时，由用户要求比较公开模板的程序、文档和测试变化。保留自己的 me.json、references/profile.json、context.md 和 .local，将必要的兼容变更提出为个人仓库维护 PR，经用户审核合并后再由周五正常同步。个人资料不回传公共模板。

## 暂停、卸载与遗忘

通过正式平台工具暂停/删除对应两项任务，不只是改本地记录。卸载全局上下文时仅移除 me-skill 标记区块；完整备份恢复前核对后来修改，不覆盖其他规则。

遗忘个人内容需检查自己的画像、全局区块、备份、导出包及远端历史的具体范围；仅删除本地文件不代表所有副本消失。
