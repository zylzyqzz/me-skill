# Me Skill · 我的分身

**每个人都可以培养自己的 AI 协作分身。** 从空白画像开始，让 AI 默认按你的习惯工作，通过真实使用不断完善，并由你掌握最终审核权。

| 能力 | 做什么 |
|---|---|
| 全局个人画像 | 在宿主支持的用户级个人指令中接入你的画像，新对话和不同项目默认带入 |
| 周一复盘 | 任务触发后回顾最近 7 天使用情况、习惯和纠正，去敏汇总成 PR |
| 周五更新 | 检查你自己的私有仓库 main，自动验证、更新并刷新常驻画像 |

本仓库是**空白公开模板**，不包含任何人的画像，也不接收你的个人周报。日常不持续抓取聊天；AI 不会凭空知道你是谁，更不会因安装文件就获得宿主没有的记忆或调度能力。

## 最简单的用法：把这段交给你的 AI

```text
请安装 https://github.com/zylzyqzz/me-skill，帮我建立自己的个人分身系统。
按 SKILL.md 和 references/setup.md 实际完成：
1. 根据我提供和授权读取的材料建立我的画像，关键未知信息集中问我。
2. 创建或核验我自己的私有仓库保存个人版本；公开模板不是我的画像仓库。
3. 把画像接入你正式支持的用户级全局个人指令，让新对话和不同项目默认带入。
4. 建立或复用周一复盘提 PR、周五自动同步个人仓库 main 的两项任务。
5. 核验并告诉我哪些已完成、哪些未验证、哪些宿主不支持。
默认两项任务均为 09:00，先确认我的时区。
使用已有 GitHub 登录，不让我把 token 发到聊天；不自动合并 PR。
```

你只需要补充：称呼、主要目标、常让 AI 做的事、沟通习惯、授权边界、验收要求和时区。不确定的内容可以留空；真实协作会为后续更新提供证据。

## 安装流程

1. 获取这个模板的完整文件。在 GitHub 生成自己的**私有模板副本**，或让 AI 创建私有仓库并导入模板文件；不要公开 fork 后往里面写个人信息。
2. 将自己的仓库安装到宿主正式支持的个人 Skill 目录，文件夹名为 `me-skill`。另一 AI 安装时从这个个人私有仓库取得已审核画像，而不是重新填写公开模板。
3. AI 完成配置、初始画像、全局接入、两项真实定时任务及验收。详细步骤见 [初始化攻略](references/setup.md)。

需要手动配置时，在安装目录运行（参数换成自己的值；`python` 指可用的 Python 3.10+）：

```text
python scripts/configure.py --repository YOUR_ACCOUNT/my-assistant --display-name "你的称呼" --timezone Asia/Shanghai
python scripts/configure.py --repository YOUR_ACCOUNT/my-assistant --display-name "你的称呼" --timezone Asia/Shanghai --write
python scripts/me.py init --platform your-ai
```

脚本不会自动创建仓库、账号或定时任务，这些由执行安装的 AI 通过宿主正式工具完成。模板未配置时不能提交 PR；空白画像不能冒充已经了解用户。日常无需每次手动调用 Skill，但首次初始化必须实际执行。

## 平时怎么用

正常提出任务即可。长期偏好请明确说“以后默认……”，临时要求说“这次……”。需要改/删画像时直接说“更新这条偏好”“忘记这项信息”。

周一查看自己的私有仓库 PR，判断证据是否真实、是否过度推断、范围是否准确、有没有敏感信息。采纳的内容应整理进入统一 `references/profile.json` 并更新个人版本；只合并周报文件不会自动改变画像。周五各 AI 再同步已审核版本。

`日常协作 → 周一复盘建议 → 你审核统一画像 → 周五各安装同步 → 后续协作更符合你`

## 两个仓库，不混用

| 位置 | 内容 | 更新规则 |
|---|---|---|
| 本公开模板 | 空白画像、通用程序和说明 | 作者维护；不提交个人证据 |
| 你自己的私有仓库 | 你的配置、统一画像、去敏提案 | 你审核；各安装周五同步 main |
| 每个安装的 `.local/` | 独立身份、观察、收据、备份、任务 id | 不提交、不复制给另一 AI |

公开模板将来升级时，可以让 AI 比较程序差异，向你的私有仓库提出维护 PR；不要覆盖你的画像、仓库地址或时区。详见 [更新与恢复](references/updates.md)。

## 能力边界与安全

需要宿主实际支持：持久文件、用户级全局指令、可访问历史、定时任务和 GitHub。没有某项能力时只能完成相应子集，不能把“文件存在”说成全局加载或任务已启用。新对话、跨项目、定时触发均需实际验收。

同一 AI 的全局个人画像不等于所有聊天内容实时共享，也不等于跨设备、跨产品自动同步。已运行会话的刷新取决于宿主。敏感信息和原始聊天不进入任何周报；私有仓库也遵循最小必要原则。

本模板没有遥测，不向作者收集使用数据；网络提交脚本只访问本地配置的个人仓库，发送前再次核验它是私有仓库。

## 开发验证

```text
python -m unittest discover -s tests
python scripts/validate_package.py --template
```

个人仓库已填写画像后，验证命令去掉 `--template`。自动测试使用合成资料，不能证明所有宿主都能全局加载、访问历史或执行调度。
